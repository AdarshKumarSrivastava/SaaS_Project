## 1. Confirmed Findings — Fix Before Any Redesign Work

### P0 — Critical, fix immediately
1. sites.controller.ts's adminLogin falls back to a hardcoded 'admin123' password when a site has no admin_password credential set. Remove the fallback entirely — a site's admin panel must be unreachable until its owner explicitly sets a password, not protected by a default anyone can find by reading the source.
2. ai.controller.ts's ingest endpoint has no ownership check on siteId. It only requires authenticate (any logged-in user), not that the requester owns the target site. Add an authorization check (verify a SiteRole for req.body.siteId and req.user.userId with an appropriate role) before allowing ingestion — otherwise any user can pollute any other site's AI knowledge base.
3. OAuth callbacks (oauthGoogleCallback, oauthGithubCallback) redirect with accessToken/refreshToken as URL query parameters. These end up in browser history, server access logs, and the Referer header. Replace with either: (a) set the tokens as httpOnly, secure cookies directly in the redirect response, or (b) redirect with a short-lived, single-use exchange code that the frontend immediately trades for tokens via a POST request.
4. Both access and refresh tokens are stored in localStorage (AuthContext.tsx), making them fully readable by any injected script. At minimum, move the refresh token to an httpOnly cookie set by the backend; keep only the short-lived access token client-side if it must stay in JS-accessible storage.
5. If the Neon database password and JWT secret that were previously committed in an earlier version of .env.example have not yet been rotated, rotate them now — they remain recoverable from git history even though the current .env.example is clean.

### P1 — Major, fix before feature/design work continues
6. Fix the SMTP_USER/SMTP_PASS vs SMTP_EMAIL/SMTP_APP_PASSWORD mismatch between auth.controller.ts (signup, resendOtp) and .env.example/hire.controller.ts, so real signup OTP emails actually send.
7. Add rate limiting to POST /api/ai/chat — it's an unauthenticated, unlimited endpoint that calls paid OpenAI completions on every request.
8. testCredential currently validates key format (prefixes, length) but does not make a real call to the external service (ImageKit, Razorpay, etc.) to confirm the key actually works. Upgrade to a real verification call per keyType before calling this feature complete.
9. logout doesn't revoke the refresh token — it remains valid for its full 7-day life after logout. Add a revocation/denylist mechanism, or explicitly document this as an accepted limitation if out of scope for now.
10. Remove the stale MONGO_URI entry from .env.example — MongoDB has been fully removed from the code, this is dead leftover.

### P2 — Confirm and note, fix if time allows
- getSite, updateSite, deleteSite rely entirely on the route-level authorize middleware for ownership checks (confirmed correctly wired in sites.routes.ts) rather than checking ownerId inside the controller body — this is fine as implemented, but confirm test coverage exists for it directly (a wrong middleware order or a future new route that forgets to attach authorize would silently reopen this).
- inviteRole is a 501 stub — acceptable for MVP, just don't let it silently look implemented in any UI.

## 3. Design System

### 3.1 Palette
--bg-base: #FAFAF8 — Page background
--bg-elevated: #FFFFFF — Cards, panels, nav
--bg-subtle: #F2F1EC — Section alternation, hover fills
--ink: #1D1D1F — Primary text
--ink-soft: #6E6E73 — Secondary text
--accent: evolve from the existing template accent, used sparingly, never as a large surface color
--line: #E5E5E1 — Hairline borders
--success: #1DAA6E — Status/positive state

### 3.2 Typography & Spacing
- Geometric/humanist sans (Inter or similar), matching or evolving the existing font-heading/font-body/font-accent Tailwind classes already in the codebase.
- Display headlines: tight tracking (-0.02 to -0.04em), heavy weight.
- Body: 16–19px, generous line-height, --ink-soft for secondary text.
- 8px base grid; large card radii (16–24px); soft multi-layer shadows over hard borders.

### 3.3 Motion Principles
1. Page transitions: extend the existing TransitionLink component — don't build a second system.
2. Scroll reveals: extend components/ui/ScrollReveal.tsx — reuse it everywhere rather than reimplementing per page.
3. Reuse the existing Lenis smooth-scroll setup (SmoothScrollProvider.tsx) rather than introducing a second scroll library; audit it for conflicts with modals, forms, and the @dnd-kit builder drag interactions specifically (smooth-scroll libraries are a common source of drag-and-drop jank).
4. Micro-interactions: buttons lift with shadow growth, cards scale 1.01–1.02 with shadow bloom, every interactive element has visible hover and focus states.
5. Loading states: skeleton loaders for data-dependent content, not blank screens or bare spinners.
6. Respect prefers-reduced-motion everywhere.
